Building classification for emergency management

Remote sensing, machine learning, Python

A machine learning pipeline that classifies 136,534 Minneapolis building footprints into three FEMA Public Assistance categories (residential, commercial, public) from multi-source remote sensing data. It reaches 96.79% accuracy and is designed to speed up disaster response resource allocation.

Built with

  • Python: scikit-learn, XGBoost, GeoPandas, Rasterio, Rasterstats, Shapely
  • Data: NAIP (0.3 m), Sentinel-2 (10–20 m), Microsoft US Building Footprints, Hennepin County parcels
  • ArcGIS Pro and an Esri StoryMap for communication

What I did

  • Engineered 23 features: NAIP spectral (9), Sentinel-2 spectral (8), morphological (4), and spatial context (2)
  • Labeled ground truth in two stages from parcel ownership keywords and land use codes
  • Applied class weighting (up to 24×), raising public building recall from 36% to 81%
  • Compared Random Forest, Linear SVM, and XGBoost; Random Forest won at 96.79% test accuracy
  • Exported results as GeoPackage and Shapefile for downstream GIS work

Findings

  • Coarse Sentinel-2 neighborhood context (37% of feature importance) far outweighed fine NAIP roof detail (2.4%): building type depends more on location than appearance
  • Building size and shape accounted for 27% of model importance
  • Class weighting recovered public building recall at a cost of only 0.23% overall accuracy

Heat risk agent-based model (team project)

Agent-based modeling, project management, Python, SQL

A simulation of how households respond to extreme heat. Each house is an agent that decides whether to go to a cooling center. Decisions are probabilistic and depend on temperature, so hotter conditions drive more movement and results vary from run to run.

My role

  • Project manager: planned the work and led the team's presentations
  • Developer: wrote parts of the model code
  • Wrote most of the project documentation

Built with

  • Python: GeoPandas, Pandas, NumPy
  • SQL database for model data
  • ArcGIS maps and dashboards

Suitable: suitability analysis web app

Web development, multi-criteria analysis, Python

An interactive web app for multi-criteria suitability analysis on your own geospatial data, with no GIS expertise or coding required.

Built with

  • Streamlit, GeoPandas, Pandas, NumPy, Folium, streamlit-folium
  • Object-oriented design: Project and Criterion models; DataLoader, SuitabilityAnalyzer, and ResultsExporter components; file, map, and boundary utilities

Features

  • Upload shapefiles, GeoJSON, and other vector formats
  • Define a custom study area boundary
  • Add criteria with scoring methods and weights
  • See inputs and results on an interactive map

GeoChat: conversational GIS

Natural language interface, API integration, Python

A Jupyter-based tool for working with geospatial data through plain-language commands instead of GIS syntax.

Built with

  • GeoPandas, Folium, ipywidgets, Shapely, Pandas, NumPy, Matplotlib, Requests
  • Nominatim, Overpass API, and OSRM routing

Features

  • Load local files or download data from URLs
  • Go to places and find nearby points of interest
  • Buffer features, calculate areas, measure distances, and get driving directions
  • Interactive map that updates with every command

Example commands: “go to New York City”, “show parks”, “buffer by 5 km”, “show route from Miami to Orlando”.

SynerGIS: parallel spatial joins (Python + Rust)

Systems programming, parallel computing, Rust, Python

A high-performance Python library for running spatial joins in parallel, with a Rust backend.

Built with

  • Rust with PyO3 bindings for Python
  • geo and geo-types for geometry, rayon for parallelism, rstar for R-tree indexing, criterion for benchmarks

Features

  • Spatial joins spread across all CPU cores
  • R-tree indexing for fast candidate lookup
  • Drops into existing Python geospatial workflows

Benchmarks against GeoPandas

  • Faster above about 200,000 features, reaching 2.6× faster at 500,000 points and polygons
  • Up to 1.55× faster when points outnumber polygons (5 million points, 50,000 polygons)
  • GeoPandas stays faster on smaller datasets and when polygons outnumber points (SynerGIS at 0.39×), which is the next optimization target
